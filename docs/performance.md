# Performance methodology

Performance claims for Uinxed-Agent 2.0 are evidence-driven. This document deliberately does not invent numbers from hardware that was not measured.

## Architecture-level changes

The Go rewrite removes several hot-path patterns from the previous React/Ink design:

- Model content/reasoning SSE deltas are delivered immediately to minimize visible latency. Partial assistant text uses a lightweight streaming renderer; only cumulative tool-output snapshots are coalesced on a small refresh window.
- Completed Markdown is cached by `(message ID, content version, width, theme)`.
- Conversation rendering materializes only the visible range plus overscan rather than re-rendering every historical message.
- Repository file completion uses a cached index and fsnotify invalidation instead of a synchronous full tree walk per keystroke.
- SQLite reads/writes are outside the Bubble Tea view function and use WAL, busy timeout, indexes and transactions.
- One shared HTTP transport per provider is reused for connection pooling/keep-alive.
- Tool concurrency is bounded by category and every run inherits cancellation.

## Reproducible benchmark command

```bash
./scripts/benchmark.sh
```

The script records:

- Go version / OS / architecture
- cold process start (`ux-agent --version` as a binary-start baseline)
- binary size
- package benchmarks including Markdown cold/cached render
- 10k-file fuzzy lookup
- SQLite 1000-message session load
- all benchmark allocation data reported by `go test -benchmem`

For an old-vs-new comparison, preserve a checkout of the Node master immediately before migration and run both on the same hardware/terminal/dataset. Do not compare numbers collected on different machines as if they were a controlled delta.

## Acceptance targets

The runtime is designed so that:

- idle state has no continuous full-screen timer/redraw loop;
- typing/mouse event handling remains independent from raw provider chunk frequency;
- provider-to-UI queues are bounded;
- 1000+ message sessions do not render every historical message per frame;
- large tool output is collapsed unless opened;
- resizing invalidates width-dependent Markdown lazily rather than reparsing on every ordinary event;
- cancellation tears down provider requests and child processes.

## Validation record

The exact checks executed during this rewrite, including the local Go/network limitation, are recorded in `docs/validation.md`. CI is the authoritative release gate and runs `go test ./...`, Linux `go test -race ./...`, `go vet ./...`, and `go build ./cmd/ux-agent` on Go 1.25 across Linux, macOS and Windows. The tag-triggered Release workflow repeats a full validation gate before its build matrix can run, so release artifacts are not produced from an unvalidated tag.

When benchmark output is collected on a concrete machine, attach or paste the raw `benchmark.txt` generated by `scripts/benchmark.sh`; that raw file is the evidence source for numerical claims.
